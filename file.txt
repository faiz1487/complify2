# Step 4: NAT Gateway Count

For production:

Create 2 NAT Gateways

NAT-A → Public Subnet A
NAT-B → Public Subnet B

Allocate Elastic IP for each.

Reason:
If one AZ fails, private services still access the internet.

Budget option:
1 NAT gateway works but creates a single point of failure.

—
Currently we use only one NAT gateway for both private subnets

     ↓
Backend API (ECS)
     ↓

     ↓

     ↓
processing/
     ↓
processed/ OR failed/
     ↓
archive/ (old data)


STEP 1 — Create S3 Bucket
Open AWS Console:
https://console.aws.amazon.com/s3/
Click:
Create bucket


STEP 2 — Configure Bucket
Bucket Name
Example:
document-processing-prod

Must be globally unique.

AWS Region
Use same region as:
ECS
RDS
Redis
Example:
us-east-1


Block Public Access
Keep enabled:
✔ Block all public access


Versioning
Optional but recommended:
Enable Bucket Versioning


Create Bucket
Click:
Create bucket


STEP 3 — Create Folder Structure
Open bucket.
Click:
Create folder

Create these folders one by one:
1. raw/
raw/

Incoming uploaded files.

2. processing/
processing/

Temporary active processing files.

3. processed/
processed/

Successfully processed outputs.

4. failed/
failed/

Failed files.

5. archive/
archive/

Old processed data archive.

Final Bucket Structure
document-processing-prod/
│
├── raw/
├── processing/
├── processed/
├── failed/
└── archive/


STEP 4 — Create SQS Queue
Open AWS Console:
https://console.aws.amazon.com/sqs/
Click:
Create queue


STEP 5 — Configure Queue
Queue Type
Choose:
Standard Queue


Queue Name
Example:
document-processing-queue


Visibility Timeout
Set:
300 seconds

(5 minutes)
Must be longer than processing time.

Message Retention
Example:
4 days


Create Queue
Click:
Create queue


STEP 6 — Create Dead Letter Queue (DLQ)
Create another queue.
Queue Name
document-processing-dlq

Queue Type
Standard

Create queue.

STEP 7 — Attach DLQ to Main Queue
Open:
document-processing-queue

Go to:
Edit
→ Dead-letter queue

Enable:
Use DLQ

Select:
document-processing-dlq

Set:
Maximum receives = 3

Save.

STEP 8 — Copy Queue ARN
Open queue.
Copy:
Queue ARN

Example:
arn:aws:sqs:us-east-1:123456789012:document-processing-queue

Keep it for next step.

STEP 9 — Copy Bucket ARN
Open S3 bucket.
Go to:
Properties

Copy:
Bucket ARN

Example:
arn:aws:s3:::document-processing-prod


STEP 10 — Allow S3 to Send Messages to SQS
Open:
SQS Queue
→ Access Policy
→ Edit

Paste policy:
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowS3ToSendMessage",
      "Effect": "Allow",
      "Principal": {
        "Service": "s3.amazonaws.com"
      },
      "Action": "SQS:SendMessage",
      "Resource": "SQS_QUEUE_ARN",
      "Condition": {
        "ArnEquals": {
          "aws:SourceArn": "S3_BUCKET_ARN"
        }
      }
    }
  ]
}


STEP 11 — Replace Values
Replace:
SQS_QUEUE_ARN
Example:
arn:aws:sqs:us-east-1:123456789012:document-processing-queue


S3_BUCKET_ARN
Example:
arn:aws:s3:::document-processing-prod

Save policy.

STEP 12 — Create S3 Event Notification
Open bucket:
document-processing-prod

Go to:
Properties
→ Event Notifications
→ Create event notification


STEP 13 — Configure Event
Event Name
raw-upload-event


Event Types
Select:
All object create events


Prefix Filter
raw/

Only files uploaded to raw/ trigger processing.

Destination
Choose:
SQS Queue

Select:
document-processing-queue

Save.

STEP 14 — Test Upload
Upload any file:
raw/test.pdf


STEP 15 — Verify SQS Event
Open:
document-processing-queue

Click:
Send and receive messages
→ Poll for messages

You should see event message.
Example:
{
  "Records": [
    {
      "eventName": "ObjectCreated:Put",
      "s3": {
        "bucket": {
          "name": "document-processing-prod"
        },
        "object": {
          "key": "raw/test.pdf"
        }
      }
    }
  ]
}

SUCCESS means event-driven pipeline works.

STEP 16 — Create ECS IAM Task Role
Open AWS Console:
https://console.aws.amazon.com/iam/
Create Role
Choose:
AWS Service
→ ECS Task


STEP 17 — Attach Permissions
S3 Permissions
AmazonS3FullAccess

SQS Permissions
AmazonSQSFullAccess


STEP 18 — Name Role
Example:
ecs-document-worker-role

Create role.

STEP 19 — Attach Role to ECS Task
Open:
ECS
→ Task Definitions

Open ingestion worker task.
Set:
Task Role = ecs-document-worker-role

Deploy new revision.

STEP 20 — Worker Processing Flow
Your ECS worker should:
1. Read SQS Message
Example:
{
  "bucket": "document-processing-prod",
  "key": "raw/test.pdf"
}


2. Download File
From:
raw/


3. Move to processing/
Example:
processing/test.pdf


4. Process Document
OCR / embedding / extraction.

5. Success
Save result:
processed/test.json

Delete:
raw/
processing/

6. Failure
Move to:
failed/test.pdf


STEP 21 — Archive Old Processed Data
Do NOT manually archive every file.
Use lifecycle rules.

STEP 22 — Create Lifecycle Rule
Open bucket.
Go to:
Management
→ Lifecycle Rules
→ Create Rule


STEP 23 — Configure Archive Rule
Rule Name
archive-old-processed-files


Prefix
processed/


Transition Rule
After:
90 days

Move to:
Glacier Instant Retrieval


Optional Delete Rule
Delete after:
365 days

Save.
